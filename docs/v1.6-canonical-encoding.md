# Canonical Silver encoding v1

Implementation: `factory/silver_contract.py` and `factory/parity.py`. Contract ID: `contoso-silver-logical-v1`. Gold KPI and ML label definitions remain exclusively in the existing dbt models.

## Governed schema and keys

The source column names, order, types, nullable rules and primary keys come from `models/source_model.json`. The derived Silver contract adds these columns/tables:

| Table | Key | Additions / uniqueness |
| --- | --- | --- |
| Source-shaped Silver tables | Original source primary/composite key | Required unique, including `(OrderKey, LineNumber)` |
| shipment_events | ShipmentEventKey | Float64 IngestionLagHours; boolean IsLateArrival |
| customer_scd2 | CustomerKey, ValidFrom, SourceEventId | Source customer columns, then SourceEventId, ValidTo, IsCurrent, IsDeleted; unique |
| quality_issues | Entity, RecordKey, Rule, EvidenceId | Entity, RecordKey, Rule, BadValue, EvidenceId; repeated quarantine records are legal |

All columns have measured null counts, not only keys. Null keys and nonnullable value violations fail even when all engines share the defect. BadValue and ValidTo permit null. The original source nullability is preserved elsewhere. Each run persists its exact `silver_contract.json`, bound by the Silver stage's artifact hashes.

Parquet string and large_string normalize to string. Timestamp physical units and zones normalize to UTC microseconds. Int32 and int64 remain distinct; decimal precision/scale must match exactly; float32 does not become float64. Missing/extra columns, duplicate column names and incompatible logical types fail before value canonicalization. Physical column order is mapped to contract order. Parquet optional/required field bits and pandas/Arrow writer metadata are excluded: nullability comes from governance and actual values. Dictionary compression is not a logical type change.

## Byte stream

`frame(payload)` is an unsigned 64-bit **big-endian byte length**, followed by payload. Lengths always count bytes, including UTF-8 multibyte sequences. Scalars are tagged:

| Value | Encoding |
| --- | --- |
| Null | ASCII `N` only |
| String | `S` + frame(exact UTF-8); no trimming or Unicode folding |
| Boolean | `B0` / `B1` |
| Integer | `I` + frame(invariant signed decimal ASCII, no leading zeros) |
| Decimal(18,2) | `D` + frame(fixed two-decimal ASCII); negative zero becomes `0.00`; excess precision/scale fails |
| Timestamp | `T` + frame(UTC ISO-8601 `YYYY-MM-DDTHH:MM:SS.ffffffZ`) |
| Float64 | `F` + frame(per-column normalized ASCII) |

Naive timestamps mean UTC, consistent with DuckDB's session/source contract. Aware timestamps convert to UTC. Sub-microsecond nonzero digits fail instead of truncating. The source CSV contract itself remains whole UTC seconds.

The only governed float column is **IngestionLagHours**: Python's shortest round-trip decimal representation is rounded to **nine decimal places, half-even**, then emitted at fixed scale. There is no pairwise epsilon comparison; values match exactly after this policy. Values on opposite rounding boundaries differ. Negative zero becomes positive zero, all NaN payloads become `nan`, positive and negative infinity become `+inf` and `-inf`. Null remains different from NaN. A new float column needs an explicit policy; ungoverned floats fail.

A row is the concatenation of each framed scalar in contract column order. A key is the concatenation of framed scalars for the governed key columns. Rows sort lexicographically by **(canonical key bytes, complete canonical row bytes)**. This is a deterministic encoding order, not a numeric presentation order. The full row tie-breaker preserves deterministic legal duplicate ordering and multiplicity.

The SHA-256 input is:

1. ASCII `CONTOSO-LOGICAL` followed by a zero byte.
2. Framed UTF-8 JSON for `{version, columns, key, unique}`, with sorted object keys, no insignificant whitespace and unescaped Unicode. Array order remains contractual; per-column float policy is included.
3. Each sorted row, framed again.

Physical Parquet bytes never contribute to the logical hash. Separate physical SHA-256 maps bind execution artifacts and detect tampering. Tests demonstrate different compression, dictionary encoding and row order with equal logical hashes.

## Comparison and failure behavior

The comparator requires distinct engines and isolated completed run directories. For local engines it verifies the compiled engine and all compiled stage successes, source and compiled-manifest identity, persisted contract, stage artifact hashes and the exact Silver file set. All runs must share source fingerprints, source SHA-256 maps and source model bytes. Spark's separate runner emits an actual Bronze/Silver-only record with the same bindings; it never claims full factory execution.

Every table reports normalized schemas, keys, row counts, uniqueness, duplicate groups, null counts/violations, logical hashes and matched state. Comparisons report exact missing/extra key counts, sample keys, changed row multiplicities and changed column values. Default samples are limited to 10 (CLI accepts 1–100); individual displayed values are capped at 256 characters. Counts and hashes cover the complete table. Artifact tampering fails the overall result while logical diagnostics still identify the affected key/column. Incomplete or incompatible input runs are rejected before any new parity file is emitted. A previously written parity file is historical evidence, not updated by a rejected attempt; use fresh output paths for separate experiments.

The CLI exits nonzero on a mismatch. CI retains deliberate value, key, null/empty, schema and persisted-tamper mismatch JSON under `negative-parity/`.

## Limits

This release's comparator is for local educational datasets. It rejects individual Parquet tables above 512 MiB of uncompressed row-group metadata before loading; Python objects, grouping and sorting require additional memory. It materializes a table from each engine. Polars requests streaming collection and records explain plans, but operators and final frames can materialize in memory; universal streaming is not certified. pandas is eager and intended for small local datasets.

The preserved CDC precedence is `(EventId, IngestedAt, Sequence)` and shipment-event precedence is `(ShipmentEventKey, IngestedAt, ShipmentKey)`. Generated duplicate rows have identical values when those ordering fields tie. Future external ingestion should govern conflicting equal-precedence events explicitly before promising deterministic winner selection. Similarly, scalable parity needs an external sort or partitioned comparator with a new, versioned evidence policy. Neither requires a second business planner.
