# V1.6 final orchestration hardening

The branch starts from fetched `origin/main` at merged PR #2, `35d1959c6ecb891b50ba45a47f44d373f76acac7`. The existing C# generator, compiler and factory contracts remain authoritative. This pass makes the optional local Cosmos path execute one full dbt build and adopt its real artifacts before reconciliation. It adds no new product architecture.

## Execution contract

`prepare_silver -> Cosmos Watcher producer -> model/test watcher sensors -> adopt -> reconcile -> ML or export -> BI -> strict Evidence build`

The generated DAG has `max_active_runs=1`, a one-slot warehouse pool and no retries. The producer must finish before synchronous consumers: local `airflow dags test` runs tasks serially, so allowing a sensor to run first would block the producer. The sensors inspect actual Cosmos XCom results. This retains model/test visibility without requiring a triggerer. No node retry or consumer fallback is certified; an additional dbt command fails the guard.

Airflow **3.3.1** and Cosmos **1.15.1** run in one environment. The factory and dbt use a separate venv with the unchanged V1.6 runtime pins: dbt-core **1.11.14**, dbt-duckdb **1.10.1**, DuckDB **1.4.5**, Polars **1.44.1**, pandas **2.3.3**, Arrow **23.0.1** and sklearn **1.7.2**. Cosmos explicitly uses subprocess invocation and the generated guarded executable. The guard invokes the real pinned dbt executable once, passes JSON logs back to Cosmos, and records the actual command, exit status, timestamps, versions and artifact hashes. An exclusive build claim rejects duplicate execution. Direct `dbt_runtime.build` also rejects Cosmos projects.

The Cosmos producer callback archives the whole-project `manifest.json` and `run_results.json` before temporary-directory cleanup. It checks actual producer type, DagRun/task identity and the upstream XCom nonce. Artifact adoption validates source/compiled hashes, input files (including the separately supplied dbt profile), project/manifest identity, invocation ID and nonce, timestamps, all **27 models and 135 tests**, zero failures/skips, callback/subprocess hashes and the canonical `warehouse.duckdb` path/hash. It copies those exact bytes to `dbt/target/` and supplies the existing `dbt_execution.json` contract, including `labelAsOf` for ML. It never builds again.

The gate reads actual DagRun and task-instance rows from its isolated Airflow metadata database after CLI completion. It requires every imported task to succeed exactly once and binds the dbt invocation to the producer task's actual time interval. `airflow_execution.json` references the task snapshot, import report and CLI log by SHA-256. `cosmos_execution.json` binds that evidence to adoption, warehouse, reconciliation, downstream stages and strict report output. Validation does not turn failed checks into successful evidence.

These are integrity and provenance checks within a trusted local run directory, not remote cryptographic attestation against a party able to rewrite every witness. A complete local DagRun is **not** evidence of an always-on scheduler, Kubernetes deployment, managed Airflow or cloud execution.

## Reproduce on Linux

```bash
dotnet build DatabaseGenerator --configuration Release
python3.12 -m venv .venv-factory
.venv-factory/bin/pip install -r DatabaseGenerator/Forge/Templates/v15/requirements.txt
python3.12 -m venv .venv-airflow
.venv-airflow/bin/pip install apache-airflow==3.3.1 apache-airflow-providers-standard \
  --constraint https://raw.githubusercontent.com/apache/airflow/constraints-3.3.1/constraints-3.12.txt
.venv-airflow/bin/pip install apache-airflow==3.3.1 astronomer-cosmos==1.15.1
.venv-airflow/bin/pip check
.venv-factory/bin/pip check
python scripts/generate_orchestration_fixture.py --downstream ml --output out/cosmos
.venv-factory/bin/python out/cosmos/factory/prepare_cosmos.py --root out/cosmos
export FORGE_FACTORY_PYTHON="$PWD/.venv-factory/bin/python"
export FORGE_DBT_EXECUTABLE="$PWD/.venv-factory/bin/dbt"
.venv-airflow/bin/python scripts/run_orchestration.py --root out/cosmos --airflow-home "$PWD/out/airflow-first"
.venv-factory/bin/python scripts/check_orchestration_runs.py --root out/cosmos --expected-runs 1
.venv-factory/bin/python scripts/test_orchestration.py -v
```

Node 22/npm must be on PATH for the strict Evidence sources and production build inside the final task. `--downstream bi` disables ML; `--downstream export` preserves `exported-not-executed` semantics and does not train a hosted model. To prove another run, reuse the generated root with a **fresh** Airflow home and a new `--logical-date`; Airflow supplies a new actual DagRun ID. The guard refuses existing Forge run state, and the multi-run checker requires distinct invocation IDs/nonces. Raw output remains under `.forge/v15/<hashed-Airflow-run-id>/`.

## Compatibility and truthfulness

The six prior workflows remain. The dedicated `orchestration-v16` gate executes ML, no-ML and export variants, with a second real no-ML DagRun and negative evidence tests. Existing workflows retain DuckDB/Polars/pandas and Spark 4.0.4 parity, direct dbt, ML legality/embargo/validation-only selection, Evidence, Spark classic/Connect, free-GCP and WPF coverage.

Only V1.6 DuckDB/Cosmos's dbt stage is promoted to `runnable` / `reconciled` using its own historical orchestration ledger. Other Cosmos engine/product combinations remain generated. Every newly assembled plan remains `currentExecutionStatus=not-executed`. Historical direct-dbt ledgers are unchanged.

Active Airflow CI and explicit V1.6 Minikube exports align to 3.3.1. The 152 audited legacy artifacts include Minikube files, so legacy and V1.5 exports retain 3.2.2 byte-for-byte. Both Helm variants are validated; this pass makes no new cluster deployment claim. Historical 3.2.2 execution records are not rewritten.
