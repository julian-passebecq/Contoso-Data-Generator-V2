# Contoso Forge V1.4.0 release-fix evidence

This pass fixes default artifact compatibility, planner implementation aggregation and current-release wording. It starts from published V1.4.0 `ec1ea2d6bb2e408480277ef11eef46333de00939` and compares audited V1.3 `407c1d250addb7b3f0cc3f9ce21f5ae676c2132d`. No runtime adapters, architecture features or schema versions were added or changed.

## Airflow byte comparison

Both revisions generated `DatabaseGenerator.Tests/Fixtures/v13-default.project.json` in the same environment, first on Windows and then in the same Linux container. Each invocation used `forge generate --project <fixture> --output <separate-output>`; that command also performs the legacy Studio compilation. Windows used SDK 9.0.101 / .NET 8.0.11 with CRLF checkouts. Linux used `mcr.microsoft.com/devcontainers/dotnet:1-8.0-bookworm`, SDK 8.0.415 / .NET 8.0.21, with LF checkouts.

| Differences from audited hash fixture | 0 | Airflow DAG and its hash in `run_manifest.json` |
| Airflow DAG bytes | 6,003 | 5,879 |
| Decoded embedded plan bytes | 2,993 | 2,899 |
| Embedded plan line endings | 94 CRLF, final LF | 95 LF |

Audited Windows DAG SHA-256: `9faa0f25bef9e08c7beacd3ffcf03cb4d4793de6f6240e55ad09454094f7264b`.

Pre-fix Linux DAG SHA-256: `c81249966cf328c51770613d2fc40f8fbf6830a07bd3e17f812360311368168f`.

The exact DAG byte diff begins at zero-based offset 538, in the Base64 string replacing `__PLAN_BASE64__`. Normalizing the outer Python text does not remove this difference. Decoding the payload reveals identical JSON values and identical LF-normalized text. The only decoded byte difference is the 94 CR bytes in Windows indentation. Both outer DAG files already use LF.

`JsonSerializer.Serialize` with indentation uses platform-dependent newlines. The compiler encoded that text before its file writer normalized line endings, so normalization could not reach the Base64 payload. V1.4's new Windows-captured hash regression exposed this existing cross-platform discrepancy; planning did not change the default pipeline semantics. The fix explicitly preserves the audited CRLF JSON indentation plus final LF before encoding. Standalone JSON files retain LF. The hash fixture is unchanged.

After the fix, Linux generation matches all 152 original audited hashes, including the DAG and run manifest. Its DAG and decoded payload are byte-identical to audited Windows V1.3. Windows also passes the unchanged 152-file compatibility test. Ordinary generation and legacy compilation retain their artifact set; Plan output stays opt-in.

## Planner and release text

Overall implementation now aggregates stage status with precedence `unsupported > reference-only > generated > runnable`. Historical `executed` adapter evidence contributes runnable capability without changing `currentExecutionStatus=not-executed`. Tests cover all eight combinations of unsupported, reference and generated stages alongside runnable/executed stages. They also cover classic, `free-gcp-connect`, `local-fast` and `open-lakehouse-iceberg` under both business scenarios.

README, the current HANDOFF, Pipeline Studio and planning evidence identify V1.4.0. The V1.3/V1.2 HANDOFF history is preserved, and independent JSON/work-order contract versions remain unchanged.
